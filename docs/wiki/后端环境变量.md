# 后端配置与环境变量

Afterglow 后端通过 `pydantic-settings` 读取环境变量和 `backend/.env`。本页覆盖当前 `Settings`
支持的全部字段；可复制的模板见
[`backend/.env.example`](https://github.com/kldhsh123/Afterglow/blob/main/backend/.env.example)。

> [!IMPORTANT]
> `.env` 包含模型密钥、访问密码和身份信息，不得提交到 Git。修改后必须完全重启后端；
> `uvicorn --reload` 不会因 `.env` 变化重建已缓存的 `Settings`。

## 加载规则

- 操作系统环境变量会覆盖 `.env`，字段名大小写不敏感；文档统一使用大写。
- `.env` 和相对路径以启动后端时的工作目录为基准。源码运行时应先 `cd backend`。
- 未知字段会被忽略，拼写错误不一定在启动时报错，请以本页和 `.env.example` 为准。
- 下表的“默认/示例”优先表示 `.env.example` 的推荐值。`CHAT_MODEL` 模板值是 `gpt-4o`，
  完全没有 `.env` 时的代码回退值是 `gpt-4o-mini`；`LABEL_MAX_CONCURRENCY` 分别是 `19` 和 `1`。
- 配置 WebUI 的字段白名单同样来自 `.env.example`，新增 `Settings` 字段时必须同步更新示例和本页。

入门配置流程见[配置参考](配置参考.md)，数据外发范围见[负责任使用与数据隐私](负责任使用与数据隐私.md)。

## 重要联动规则

- `RELATIONSHIP_TYPE=custom` 时 `RELATIONSHIP_DESCRIPTION` 必填。
- `SELF_UID` / `FRIEND_UID` 支持逗号分隔多账号；不要把不同人合并成一个身份。
- `LIFE_*` 留空时复用主模型；`RESPONSE_POLICY_*` 再回退到 Life 链。
- `QUERY_REWRITE_*` 和 `SCHEDULE_*` 留空时优先复用 `LABEL_*`，然后回退到 Policy / Life / 主模型。
- `RERANK_*` 留空时复用 Policy / Life / 主模型；`ADAPTIVE_CHUNK_*` 优先复用 Label，再回退到 Life / 主模型。
- `VISION_ENABLED=true` 且 `CHAT_MODEL_SUPPORTS_VISION=false` 时，必须配置独立 `VISION_API_URL` / `VISION_API_KEY` / `VISION_MODEL`。
- `WEB_FETCH_ENABLED` 受 `WEB_ACCESS_ENABLED` 总开关控制。
- `WINDOW_OVERLAP` 必须小于 `WINDOW_SIZE`；`ADAPTIVE_CHUNK_MAX_CHARS` 必须不小于 `ADAPTIVE_CHUNK_TARGET_CHARS`。
- 更换 Embedding 模型或维度后不能复用旧向量库，需要重建索引。
- `WRITEBACK_VECTORIZE=false` 会用零向量写入 Live 消息，这些消息不参与语义向量召回。

## 主聊天模型

| 环境变量 | 默认/示例 | 作用 |
|---|---:|---|
| `OPENAI_API_KEY` | 留空 | 主聊天模型的 API 密钥。 |
| `OPENAI_BASE_URL` | `https://api.openai.com/v1` | OpenAI 兼容基础 URL，不要重复填 `/chat/completions` 或 `/responses`。 |
| `CHAT_MODEL` | `gpt-4o` | 生成最终回复的模型；无 `.env` 时代码回退为 `gpt-4o-mini`。 |
| `CHAT_API_PROTOCOL` | `chat_completions` | 主模型上游协议：`chat_completions` 或 `responses`；只影响主模型。 |
| `CHAT_TIMEOUT_SECONDS` | `60` | 主聊天模型请求超时秒数，必须大于 `0`。 |
| `LLM_REASONING_EFFORT` | `null` | OpenAI 兼容 LLM reasoning effort；`none`, `low`, `medium`, `high`, `xhigh` 会传给上游，`null` 不传该字段。适用于主聊天、Life、互动决策、Schedule、Query Rewrite、Adaptive Chunk、Label、VLM；不作用于 Embedding、搜索、Rerank。 |

Responses 模式会向上游发送 `store=false`，不会为了使用 Prompt 缓存而持久化响应。Prompt 缓存由支持它的上游自动处理，是否命中仍取决于服务商能力、输入长度和前缀是否完全一致；切换协议不代表必然节省 token。调试端点的 `model_chain[].response.usage.cached_tokens` 可查看上游报告的缓存命中 token 数。生活状态、互动决策、Query Rewrite 和 LLM Rerank 等辅助模型仍使用 Chat Completions 协议。
